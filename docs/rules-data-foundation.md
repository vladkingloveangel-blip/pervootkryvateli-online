## Канонические данные

`rules/index.js` экспортирует неизменяемый справочник из предметных JSON-модулей:

| Файл в rules/ | Содержание |
| --- | --- |
| metadata.json | Версия схемы, источник и SHA-256 исходного DOCX |
| fleet.json | Четыре класса кораблей, уровни I–VI, улучшения, сопровождение |
| economy.json | Товары, ресурсы, здания, цепочки уровней, доход, защита, ранги, отряды |
| islands.json | 28 карточек приложения А, ссылки и структурированные разовые награды |
| politics.json | Шесть государств, итоговые призы, 49 поручений |
| sea.json | Три морские колоды по приложению Б |
| events.json | 26 событий плавания и шесть колод вражды по 10 карт |
| legends.json | Сокровища, легендарные карты, десять мест, именные карты и экспедиции |
| characters.json | Шесть персонажей Адмиралтейства и параметры способностей |
| session.json, scoring.json | Партия, действия, армия, флот, боевые параметры и титулы |
| implementation.json | Поля с готовыми данными и этапами будущих потребителей |

`schemaVersion: 1` — версия структуры данных. `master-2026-09-28-data-v1` —
технический идентификатор набора, не выдуманный номер авторской редакции.
В самом источнике указана основа «редакция 0.10», решения от 28 сентября 2026.
Числовые таблицы имеют приоритет над примерами и описательными абзацами:
итоговый приз Кадингира — 50, красная колода использует артиллерию 15–28.

`map-config.js` сохраняет программную геометрию 28×28. Экономические поля
островов присоединяются через `rules/views.js`. Координаты, островные клетки,
Цитадель, опасности, якоря и легендарные отметки сверяются с хешем исходной main.
Изображение карты не участвует в расчётах.

## Данные и механика

Цены, характеристики, параметры эффектов, условия карточек и ссылки находятся
в данных. Проверки доступности, переходы состояния, выбор целей и применение
эффектов остаются в `game-logic.js` и `server.js`.

`game-data.js` — совместимый вход для существующего приложения.
`rules/runtime.js` создаёт действующее представление справочников и применяет
явные исключения из `rules/compatibility/legacy.json`. Канонические данные
отдаются отдельно через `GET /api/rules`; этот endpoint не содержит комнат,
закрытых рук или порядка вытянутых колод. UI использует действующие каталоги
из `roomState`, включая `balanceCatalog`, а не будущие цены с ещё отсутствующей
механикой. `iconKey` — семантический ключ, независимый от emoji и файлов графики.

Чтобы изменить цену товара, меняйте `economy.goods[id].price`; цену ступени
здания — `economy.buildings[id].levels[level].price`; морскую карту — строку
`sea[color]`. Для первого уровня здания также синхронизируйте его обзорное
поле `price`. Не редактируйте цены в движке или UI. Обновите исходный fixture
только при изменении авторского источника, затем запустите `npm run test:data`.
Добавляя сущность, задайте стабильный ID, название, iconKey и существующие ссылки.
Новый тип эффекта требует обработчика соответствующего этапа; до его появления
поставьте `availability: { status: 'data-ready', consumerStage: N }` и исключите
сущность из действующих покупок/выдачи. Произвольный текст не исполняется.

## Что подключено

Используются новые цены уровней, обычных улучшений и сопровождения; артиллерия
бригантины 4, боевого сопровождения 5; характеристики улучшений и отсутствие
бонуса движения уровней I–VI. Новые покупки ограничены VI.
Подключены цены строительства/повышения, товаров и редких промыслов, защита
укреплений, данные новых островных карточек, денежные награды и морские таблицы.
Доход, поддержка бастионов, места верфей, стоимость сопровождения, рота,
штраф якоря, добыча и длительности эффектов читают параметры. Позднее авторским решением цифрового блока отдельная контрактная премия была полностью удалена.
Разовые подарки Чертога и Кисалинии берутся из карточек.

Данные четырёх навигационных улучшений, шести общественных зданий, персонажей,
Мори, маршрутов поручений, именных карт и экспедиций пока не включают их механику.

## Совместимость и отложенные изменения

Сохранения не мигрируются и не пересоздаются. Сохраняются записанные острова,
порядок/значения уже созданных колод, незавершённые решения и устаревшие предметы.
Новые комнаты получают `rulesDataVersion`, `rulesSchemaVersion`, `runtimeProfile`.
Отсутствие этих полей у старой комнаты допустимо. Расчёт характеристик использует
текущий runtime-справочник: это сохранение состояния, а не заморозка старого баланса.

Временно остаются:

- Этап 2 подключён отдельно: 4–6 игроков, стартовые 15, ведущий и шесть
  полных личных кругов. Прежние значения сессии в legacy.json сохранены
  только как исторические сведения о старых комнатах.
- Этап 3: чтение VII уровня, Фор-марселя и судна Ландина из старых сохранений.
  Покупка отменённых сущностей закрыта, новый захват Ландина судно не выдаёт.
  Старое уже ожидающее решение о замене сопровождения разрешается прежним кодом.
- Этап 4: прежние площади продвинутых зданий, пределы ветвей и городские отряды
  сохраняются только там, где это нужно для чтения старых состояний. Старое рудное
  сокровище допускается как legacy-данные сохранений; новые розыгрыши используют
  четыре независимых равновероятных цифровых результата, включая полный трюм алмазов.
- Этап 5: прежние переходы политики, пять активных государств, единая слава,
  платная замена поручения, старые обработчики вражды и выбор сохранения призовых
  зданий. Денежные параметры вражды и итоговых призов уже читаются из master.
  Старая ничья, третья атака и захват строений не перерабатывались.
- Этап 6 завершён: события и легендарные награды синхронизированы с текущим
  каноном. Легендарные награды и сокровища используют цифровые случайные источники;
  старые физические поля колод сохраняются только как совместимость сохранений там,
  где их полная миграция отложена на отдельный цифровой блок.
- Этап 7: итоговые титулы и полная политика миграции сохранений.

## Авторские решения и открытые вопросы

Р05 и Р06 закрыты на этапе 6: легендарная награда выбирается цифровым случайным
образом из четырёх типов, а все десять легендарных мест имеют утверждённое правило
первого открытия. R07 закрыт цифровым блоком 1: у четырёх редких промыслов нет
уровней вообще, и в канонических данных у них отсутствует поле `levels`. R21 также
закрыт: отдельной механики контрактов нет, а доставочное поручение не меняет цену
продажи.

Расхождение по физическим копиям сокровищ больше не является открытым вопросом:
четыре результата выбираются независимо и равновероятно, поэтому `treasureDeck`,
число копий и сброс не являются частью новой механики. R29 остаётся открытым и
перенесён в отдельный цифровой блок серверной видимости игровой информации.

## Проверки и граница совместимости

`npm run test:data` сверяет мастер-таблицы, эффекты и закрытые поля их типов,
ID, ссылки, карты, цепочки зданий, производные обзорные поля и отложенные
потребители. Негативные случаи проверяют, что валидатор обнаруживает испорченные
цены, защиту, доход, продукцию, площади, цепочки и ссылки.

`npm test` также покрывает старый runtime-профиль и сохранённые комнаты. Тест
хранилища сохраняет незавершённые решения и уже вытянутые карты, включая
исключённые из нового набора. Серверный тест запускает настоящий сервер с
тестовым pg-mem, сохраняет комнату, убирает у снимка новые поля версий и
восстанавливает его после перезапуска. Снимок содержит VII уровень,
Фор-марсель, судно Ландина, прежние площадь/гарнизон/ресурс Асигория, старую
морскую карту, рудное сокровище и ожидающую замену сопровождения. Проверяется
сохранение этих фактов и применение новых характеристик к восстановленному
кораблю. Production-база при этом не читается и не изменяется.

Профиль `rules/compatibility/legacy.json` проверяется отдельно: ссылки на
мастер-карты, призовые здания, временное распределение легендарных карт,
отменённые сущности и старые значения обязаны быть согласованными. Этот
профиль не меняет каноническую редакцию и не является ответом на Р05.

Числовые ожидания старых сценариев заменены по мастер-таблицам; сценарии ничьих
получили входные силы, дающие ничью с новым балансом. Старые поведенческие
ожидания отложенных механик пока явно являются compatibility-проверками.

`test/ui-data-smoke.cjs` запускается в headless Edge через установленный Playwright:
360/390/412/1280 px, отсутствие горизонтального скролла, границы панели,
44px кнопка, значения каталога и одиночная отправка при двойном тапе. Используется
тестовый снимок для UI; это не сквозной игровой сценарий. Переменные запуска:
`PLAYWRIGHT_MODULE_PATH`, `BROWSER_EXECUTABLE`, необязательная `UI_ARTIFACT_DIR`.

## Результат этапа 1

Балансные цены и подписи UI читаются из `rules/` через runtime-каталоги:
классы кораблей, улучшения, сопровождение, рота, разовые награды, легендарные
эффекты, границы игроков, число мест и общие лимиты. Оставшиеся числовые
литералы в движке/UI относятся к формулам, индексам, геометрии, порядку
действий, масштабированию и техническим ограничениям. Старые параметры,
нужные для сохранённых комнат и пока действующей механики, явно находятся в
`rules/compatibility/legacy.json`. Новая механика из следующих этапов не
включена. Числовые ожидания старых сценариев обновлены по таблицам; входные
силы сценариев ничьей подобраны для обновлённых характеристик. Поведенческие
проверки отложенных механик остаются проверками совместимости.

Перед передачей на review выполняются `npm run check`, `npm test`,
`npm run test:data`, `git diff --check` и UI smoke. Результаты конкретного
запуска фиксируются в отчёте к ветке.

Main, production-база и deploy не затронуты. Render не использовался.
